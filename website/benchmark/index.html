Benchmark

RequestTailor's performance budgets are release gates. This page shows the latest measurement of RequestTailor and of the other desktop API clients that were installed on the same machine, measured the same way. The script and the raw results are in the repository, so anyone can run it again.

How it is measured

  • Same machine, same run. All apps are measured one after the other by the same script, with the same number of starts. The hardware, the operating system, the app versions and the load average are recorded with the results.
  • Medians. Each app is started 10 times. The first start is discarded (a new binary pays for code-signing checks and cold disk caches), the result is the median of the other 9. Memory is the median of the last 3 starts.
  • Warm operating system caches. The numbers describe a start as when you open the app for the second time that day. A start right after booting the machine is slower for every app and is not measured.
  • No accounts, no network. Other apps are started with a fresh, empty profile shared by their starts, and their web content goes through a proxy address that does not answer, so nothing reaches an account or a server. An app that asks for a sign-in is measured to its first window, the sign-in or start screen.
  • Nothing else is stopped. The script only stops processes it started. If an app is already running, it is not measured.

Run it yourself

git clone https://github.com/clouddnagmbh/requesttailor
cd requesttailor
npm ci --ignore-scripts
npm run build -w apps/desktop            # the release build that is measured
node scripts/bench/run.mjs --browser     # writes bench/results/<date>-<os>.json and .md

Apps in other places are given with --app postman=/path/to/Postman.app. The details, including what each option does, are in bench/README.md; the budgets themselves in perf/README.md.
