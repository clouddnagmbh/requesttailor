OData for S/4HANA, CAP and RAP

The OData plugin turns RequestTailor into a client that knows how SAP services behave: it reads $metadata, fetches CSRF tokens, keeps ETags, builds $batch requests and runs draft actions. Your requests stay plain files.

Download OData guide

Optional, and your choice. The OData plugin ships with the app but is switched on only if you choose SAP and OData when the app starts for the first time. If you don't, you see nothing of SAP. The RequestTailor core contains no SAP-specific code; the plugin uses the same public plugin API as any other plugin.

What the plugin does

Entity browser

Reads $metadata of V2 (EDMX 1.0) and V4 services and shows entity sets, types, keys, navigation properties and operations. The model is cached per service root.

Query builder

$filter, $expand, $select, $orderby, $top, $skip, and $count (V4) or $inlinecount (V2), offered from the service model and written back into the request URL.

CSRF tokens

Before a POST, PUT, PATCH, MERGE or DELETE, the plugin fetches an X-CSRF-Token in the same session as the request (the token is bound to the session cookie) and sets it. After a 403 with X-CSRF-Token: Required it fetches a new one.

ETags and If-Match

Remembers ETag headers and @odata.etag or __metadata.etag per entity, and sets If-Match on updates and deletes that do not have one.

$batch

Composes $batch bodies with read parts and changesets: multipart for V2 and V4, and the JSON batch format for V4. The response is shown part by part.

Drafts

Draft actions for draft-enabled entity sets: Edit, Prepare, Activate and Discard in RAP; draftEdit, draftPrepare, draftActivate and discard in CAP.

DEV, QAS, PRD

Creates one environment per system from a template: host, sapClient, sapLanguage, user, and the password as a secret without a value. Adds sap-client and sap-language to every URL unless it has them.

Gateway errors

For an answer of 400 or more with an OData error body (V2 JSON and XML, V4 JSON), a note and an Error tab show the code, the message, the transaction ID and the resolution hints of the system.

Server time

Switch Measure server time on for a service and the plugin adds sap-statistics: true and shows what the header reports (gateway, application, database) as timing segments next to the total. The header format is read tolerantly and has not been checked against a real system yet.

Paging rules

Rules for @odata.nextLink (V4) and d.__next (V2), so rt send --all-pages and the app follow and merge the pages of an entity set. A rule you write for a request wins.

Clean-up rules

Data for the test-data journal: a created entity is put back with a DELETE to the URL the server named (Location, OData-EntityId or __metadata.uri), changes with If-Match from the ETag. Drafts are not undone, and the reason is shown.

Copy as ABAP

A tab turns the OData request into an ABAP snippet for ABAP Platform (cl_http_client) or ABAP Cloud (cl_web_http_client_manager), with placeholders instead of logon data.

Importers

Creates requests from a $metadata file: list, read by key, create, update and delete as the entity set allows, plus its operations. Also reads API specifications you have downloaded from the SAP Business Accelerator Hub (EDMX, or OpenAPI with x-sap extensions). It also reads an exported SAP BTP destination: one environment per destination with host, client and, for Basic or OAuth 2.0 client credentials, the secrets as names without values.

One collection, three systems

Environments are files too, so the same requests run against DEV, QAS and PRD. Only the host, client and user differ; passwords stay in your keychain.

# environments/QAS.yml
name: QAS
variables:
  - name: baseUrl
    value: https://s4-qas.example.com
  - name: sapClient
    value: "200"
  - name: sapLanguage
    value: EN
  - name: user
    value: JDOE
  - secret: true
    name: password

Three example collections

The repository contains three collections that run against a local, synthetic OData test server. Each has read, create, update and $batch requests.

CollectionShows
examples/s4hana-salesOData V2 in SAP Gateway style: sales orders, $expand, MERGE, a function import, $batch with a changeset
examples/cap-bookshopA CAP bookshop as OData V4 with drafts and through the V2 adapter, JSON and multipart $batch
examples/rap-salesorderA RAP business object with the whole draft lifecycle: Edit, Prepare, Activate, Discard

What it does not do

  • It speaks OData over HTTP. RFC, BAPI calls, SOAP services and SAP GUI are not covered.
  • It contains no SAP software and no SAP data. The test services in the repository are written from the public OData specifications and documented SAP Gateway behaviour.
  • Sign-in uses the core's methods: Basic, OAuth 2.0 (including the SAML 2.0 bearer assertion flow) and client certificates.
