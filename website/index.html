An API client that stays yours

RequestTailor keeps your requests as plain text files in your Git repository. There is no account and no cloud. The same Rust core runs on the desktop, in the browser and in your pipeline, so a request that works in the app works in CI.

What it stands for

Files are the truth

A request is a readable YAML file in the OpenCollection format, one file per request. Diffs and reviews work in any Git tool. The app is only a view on the folder, and reading and writing a file leaves it byte for byte as it was.

No account, ever

Download, open a folder, send. Everything works offline. The free edition makes no connection to our servers: no login, no telemetry, no update check.

Secrets stay local

Secret values live in your operating system's keychain or come from your secret manager. The collection holds only the variable name. A built-in scanner refuses commits that contain credentials.

Same core everywhere

The desktop app on macOS, the web app in WebAssembly and the rt command line share one core. A conformance suite runs the same cases against the native and the WebAssembly build.

Desktop, web, command line

SurfaceWhat it is
DesktopA native app for macOS (Tauri). On Windows and Linux, use the web app or the command line. Opens collection folders directly, keeps secrets in the OS keychain, has Git built in.
WebThe same interface in the browser, with the core compiled to WebAssembly. Folders are opened with the browser's file access. Requests the browser blocks (CORS, client certificates) can go through rt agent, a companion on your own machine.
Command linert send sends a request from a collection and prints a JSON report, rt run runs a folder with its tests, rt import converts other tools' exports, rt scan finds credentials before they reach Git.
MCP serverrt mcp offers a collection to AI agents as tools. Agents see no secret values, and writes to production wait for your approval. How it works

What is in it

  • Opens OpenCollection YAML collections, the format Bruno writes, without changing them.
  • Imports Postman, Insomnia, OpenAPI, cURL, HAR and .http files, with a report of everything that could not be carried over exactly.
  • Variables in layers with a visible origin: global, collection, environment, folder, request, runtime.
  • Authentication: Basic, Bearer, API key, OAuth 2.0 (client credentials, password, authorization code with PKCE, device code, SAML 2.0 bearer), AWS Signature Version 4, client certificates.
  • Git without a staging area: commit, branches, pull, push and conflict resolution in the app.
  • Large responses stay in the core; the interface fetches only the lines on screen.
  • History without bodies or header values, and search across the collection.
  • Plugins as sandboxed WebAssembly modules, on every surface.

Plugins instead of a heavy core

Protocols and domain knowledge come as plugins on a public, versioned plugin API. A plugin is a single WebAssembly file: no native code, no file system, and network access only to the hosts you grant. The first one is the OData plugin for SAP S/4HANA, CAP and RAP. Write your own.
