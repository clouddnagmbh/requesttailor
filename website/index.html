An API client that stays yours

RequestTailor keeps your requests as plain text files in your Git repository. There is no account and no cloud. The same Rust core runs on the desktop, in the browser and in your pipeline, so a request that works in the app works in CI.

What RequestTailor is

RequestTailor is an open-source (Apache 2.0) API client with a Rust core. It runs natively on macOS, in the browser as WebAssembly, as the command line rt and as an MCP server for AI agents. A request is a readable YAML file in the OpenCollection format, kept in your Git repository. There is no account, it works offline, secrets stay on your machine, and it never connects to RequestTailor servers.

What it stands for

Files are the truth

A request is a readable YAML file in the OpenCollection format, one file per request. Diffs and reviews work in any Git tool. The app is only a view on the folder, and reading and writing a file leaves it byte for byte as it was.

No account, ever

Download, open a folder, send. Everything works offline. The free edition makes no connection to our servers: no login, no telemetry, no update check.

Secrets stay local

Secret values live in your operating system's keychain or come from your secret manager. The collection holds only the variable name. A built-in scanner refuses commits that contain credentials.

Same core everywhere

The desktop app on macOS, the web app in WebAssembly and the rt command line share one core. A conformance suite runs the same cases against the native and the WebAssembly build.

What is in it

Requests and protocols

HTTP, GraphQL, gRPC (with server reflection), WebSocket and Server-Sent Events. Auth: Basic, Bearer, API key, OAuth 2.0 (client credentials, password, authorization code with PKCE, device code, SAML 2.0 bearer), AWS Signature Version 4 and client certificates. Scripts and tests run in a sandbox. Getting started

Collections as files

Opens OpenCollection YAML, the format Bruno writes, without changing a byte. Imports Postman, Insomnia, OpenAPI, Swagger, cURL, HAR and .http files, with a report of every loss. Several collections at once, a New… dialog, variable completion with origins. Collections as files

Git client

History graph, wizards that explain before they act and can undo, field-by-field diff and merge, blame, lost-work recovery, bisect, compare by running two versions, pull requests for GitHub and GitLab, and a merge driver for plain git. Git client

Check and inspect

Passive response checks and security hints tagged by OWASP API Security Top 10 (2023), a JWT reader, rate limits, pagination, trace ids, saved JSONPath views, a local webhook inbox. Check responses

Safety and quality

A production guard, rt send --watch, snapshots, rt lint, rt compare-env, a test-data journal, a two-user access check and rt shrink. Safety and quality tools

Share and copy

Share links that keep the request in the URL fragment: no upload, no secrets. Copy as cURL, fetch or Python. Share and copy

AI with your own key

Anthropic, OpenAI, Azure OpenAI, Gemini, Mistral or a local model. Off by default, with a preview of what is sent and secrets masked. Nothing goes through our servers. AI assistants

Agents and plugins

rt mcp offers collections to AI agents with approvals and an audit log; the app tests MCP servers. Plugins are sandboxed WebAssembly modules. MCP server and plugins

Plugins instead of a heavy core

Protocols and domain knowledge come as plugins on a public, versioned plugin API. A plugin is a single WebAssembly file: no native code, no file system, and network access only to the hosts you grant. The first one is the OData plugin for SAP S/4HANA, CAP and RAP. Write your own.

Questions people ask

Is RequestTailor free?

Yes. The source code is under the Apache License 2.0 and the app, the rt command line and the web app are free to use. What is free stays free. The name and logo are not under the Apache license.

Does RequestTailor need an account?

No. There is no sign-in, license key or registration. Download, open a folder, send a request. The app makes no connection to RequestTailor servers: no telemetry and no update check.

Does it work offline?

Yes. Everything works offline except the requests you send and the Git remotes you pull from or push to. Mock servers, collections, history, diff and the response checks run on your machine.

Where are my secrets stored?

Secret values live in the operating system keychain on the desktop, or encrypted in the browser storage in the web app. Collections hold only the variable name. Values can also come from 1Password, Vault, AWS, Azure or Google Cloud through their command-line tools. A scanner refuses commits that contain credentials, and AI calls mask secret values.

Can I import from Postman, Bruno, Insomnia or OpenAPI?

Yes. rt import and the app read Postman collections (v2.0 and v2.1) with environments, Insomnia exports (v4 and v5), OpenAPI 3.x and Swagger 2.0 (also multi-file and zip), cURL, HAR and .http files, and report everything that could not be carried over exactly. Bruno collections in OpenCollection YAML open directly, unchanged.

How does it work with Git?

A request is a YAML file, so Git works as it does for code. The app has a built-in Git client with a history graph, plain-language wizards with undo, field-by-field diff and merge, blame, bisect and pull requests for GitHub and GitLab. rt merge-driver lets plain git merge collection files field by field.

Can I use it in CI?

Yes. rt run sends a collection or a folder with the same core as the app, reports tests and assertions as text, JSON or JUnit, and exits with code 4 when a test fails. There is a Docker image and a GitHub Action.

Does it support OData and SAP?

Yes, as an optional plugin on the public plugin API: OData V2 and V4 for SAP S/4HANA, CAP and RAP, with CSRF tokens, ETags, $batch, drafts, Gateway errors and DEV/QAS/PRD landscapes. The core contains no SAP-specific code, and you see nothing of SAP unless you choose it at first start.

Can AI agents use my collections through MCP?

Yes. rt mcp offers a collection to agents as tools over the Model Context Protocol. Access is read-only by default, per environment; writes to production wait for your approval, agents never see secret values, and every call goes into a local audit log. The app also tests MCP servers as a client.

Can I use AI without sending my data to you?

Yes. RequestTailor has no AI service. The assistants are off by default and use your own key for Anthropic, OpenAI, Azure OpenAI, Gemini or Mistral, or a model on your computer through an OpenAI-compatible address such as Ollama. Calls go from your device to that provider, with a preview of what is sent and secret values masked.

Which platforms does it run on?

The desktop app runs on macOS. The web app runs in the browser with the core compiled to WebAssembly. The rt command line runs on macOS and Linux and comes as a Docker image. There are no desktop installers for Windows and Linux.
