Download

The macOS app and the rt command line are published on the project's GitHub releases page, together with a checksum file and its signature.

The first release is being prepared. Until it is published, the links below lead to the empty releases page. You can build everything from source in the meantime; see the README.

Windows and Linux: use the web app or the command line. There are no desktop installers for Windows and Linux.

Command line: rt

SystemFile
macOS (universal)rt_<version>_macos_universal.zip, signed and notarized
Linux x86_64, any distributionrt_<version>_linux_x86_64.tar.gz (static binary)
Linux aarch64, any distributionrt_<version>_linux_aarch64.tar.gz (static binary)

Unpack it and put rt on your PATH. rt --version prints the version. The CLI guide has the commands; rt run runs a collection in a pipeline and writes JUnit and JSON reports.

Docker image and GitHub Action

For pipelines, rt also comes as a container image (Linux, amd64 and arm64):

docker run --rm -v "$PWD:/work" ghcr.io/clouddnagmbh/rt run . --reporter junit=junit.xml

In GitHub Actions, the action clouddnagmbh/requesttailor/github-action downloads rt from the release, checks it against SHA256SUMS and runs the collection. Its README in the repository has examples.

Web app

The web app is part of the repository and runs from it (npm run dev -w apps/web). A hosted version is not part of this release.

Verify what you downloaded

Every release has a SHA256SUMS file with the SHA-256 checksum of each file, and SHA256SUMS.asc, a GPG signature of that file made with the project's release key.

1. Check the checksum

# macOS
shasum -a 256 -c SHA256SUMS --ignore-missing

# Linux
sha256sum -c SHA256SUMS --ignore-missing

2. Check the signature of the checksums

gpg --import release-key.asc
gpg --verify SHA256SUMS.asc SHA256SUMS

The output must say Good signature and show this key fingerprint:

Release key fingerprint: published with the first release

Compare the fingerprint here, on this website, rather than with the key file from the release itself: someone who could replace the files on the release could replace the key there too.

3. The operating system's own check

# macOS: should say "accepted" and "source=Notarized Developer ID"
spctl --assess --type execute -vv /Applications/RequestTailor.app

Updates

The app does not check for updates by itself, because it makes no connection you did not ask for. To hear about new versions, watch the repository's releases on GitHub or subscribe to the releases feed.
