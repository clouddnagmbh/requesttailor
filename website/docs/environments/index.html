Environments and secrets

Values that differ between systems live in environments. Values that must stay secret never enter the collection folder.

Where a variable comes from

Variables are written {{name}} and resolved in layers. A later layer wins:

  1. Global
  2. Collection (opencollection.yml)
  3. Environment (environments/<name>.yml)
  4. Folder (folder.yml)
  5. Request
  6. Runtime (for example --var on the command line)

The response view and the JSON report of rt send show for each variable which layer it came from, and list placeholders that had no value.

Secret variables

A secret variable is declared in the environment file without a value:

name: Staging
variables:
  - name: baseUrl
    value: https://api.staging.example.com
  - secret: true
    name: apiToken

You enter the value once in the app. The desktop app keeps it in the operating system's keychain (Keychain on macOS, Credential Manager on Windows, Secret Service on Linux); the web app keeps it encrypted in the browser's storage. Values are added only when a request is sent, and reports show them as ***. OAuth 2.0 tokens are kept the same way.

Secret managers

An environment can read secrets from a secret manager through that manager's own command line, with your existing login. The file holds only the reference:

name: Staging
externalSecrets:
  type: one-password
  variables:
    - name: apiToken
      secretReference: op://Staging/api/token
typeCommand line used
one-passwordop
hashicorp-vault-server, hashicorp-vault-cloudvault
aws-secrets-manageraws
azure-key-vaultaz
gcp-secrets-managergcloud

Values are held in memory only and masked in every report. The reference fields of each type are listed in the CLI reference.

Secret scanner

Before every commit from the app, and with rt scan in a pipeline or Git hook, RequestTailor looks for credentials typed into collection files: known token formats, private keys, Bearer and Basic credentials, passwords in URLs and values of credential-like fields. A commit with findings is refused. Values that are only variables, masks such as *** and placeholders are not findings. A line that is not a credential can be marked with a # rt-scan:allow comment.

Client certificates

Client certificates (PEM or PKCS#12) are configured per collection or per environment and used by the desktop app and the command line. Browsers do not let web pages present client certificates, so the web app reports a clear TLS error instead.
