MCP server

The Model Context Protocol lets AI agents call tools. rt mcp offers a collection to coding agents as tools over stdin and stdout. It is part of the rt command line and uses the same core as the apps, so an agent sends requests exactly as you would, from the same collection files.

Connect an agent

claude mcp add requesttailor -- rt mcp /path/to/collection

Other clients (Cursor, VS Code, Claude Desktop) take the same command in their JSON configuration:

{
  "mcpServers": {
    "requesttailor": {
      "command": "rt",
      "args": ["mcp", "/path/to/collection", "--env-default", "DEV"]
    }
  }
}

Tools

ToolWhat it does
list_requestsPath, name, method and effect (read or write) of every request.
get_requestOne request as in its file; credentials are masked.
list_environmentsThe environments the agent may use, with access and production flag. Secret variables appear by name only.
send_requestSends one request and returns the report with secrets masked.
run_folderRuns a folder or the whole collection like rt run. Every request is checked on its own.

GET, HEAD, OPTIONS and TRACE read; every other method writes. A GraphQL request reads unless its document contains a mutation. gRPC writes, and a WebSocket request writes as soon as it sends messages.

Rules for agents

  • Access per environment. In the app, "Agent access" sets none, read or write for each environment; the rule is stored in opencollection.yml. The default is read only.
  • Approval for production. A request that writes to an environment marked as production waits for you. Approve or deny it in the app banner, with rt approvals, rt approve <id> and rt deny <id>, or in your client if it asks. No answer within five minutes counts as a denial, and nothing is sent.
  • No secret values. Agents work with variable names. Values come from the OS keychain (as for rt send and rt run), from secret managers or from --var, and are masked in everything the agent gets back, also when a server echoes them.
  • Audit log. Every tool call is written to a local log (agents/audit.jsonl in the data folder). Nothing leaves your machine.
  • Fixed policy. rt mcp reads the access rules once at start, so an agent that edits files cannot give itself more access.

The full reference, with all options and the security model, is crates/rt-cli/README.md. Testing other MCP servers is the other direction: rt mcp-test runs the saved MCP tests of a collection.
