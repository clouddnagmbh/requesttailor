Getting started

From download to the first response in a few minutes, without an account.

1. Install

Get the app for macOS from the download page and check its signature, then open the disk image and drag RequestTailor to Applications. On Windows and Linux, use the web app or the rt command line from the same page.

2. First start

The app asks once which extras you want. Choose SAP and OData if you work with OData services; this switches on the bundled OData plugin. You can change it later in the plugin settings. Nothing else happens at first start: no account, no sign-in, no network connection.

3. Open or create a collection

A collection is a folder with an opencollection.yml file at its root. Open an existing folder (for example a Bruno collection in OpenCollection YAML, or one of the examples), create a new one, or import from Postman, Insomnia, OpenAPI, cURL, HAR or .http files. Each request is a file in that folder; see Collections as files.

4. Choose an environment

Environments hold the values that change between systems: host, user, client. Secret values (passwords, tokens) are entered once and kept in the operating system's keychain, not in the folder. See Environments and secrets.

5. Send

Pick a request and send it. The response view shows status, headers, body, timing and which variables were used and where they came from. Large responses stay fast: only the lines on screen are loaded. Next time, the app reopens the last collection and request, so sending again takes at most two keystrokes.

6. Commit

The collection is ordinary files, so commit it with the built-in Git view or any Git tool. Before every commit from the app, a scanner checks the files for credentials and refuses the commit if it finds one.

7. Run it in a pipeline

The same request runs on the command line with the same core:

rt send users/get-user.yml --env Staging --var token="$API_TOKEN" --pretty

See Command line: rt.

AI assistant

The app can write a request from a description, explain a failed response and suggest tests for a request. The assistant is off by default and RequestTailor has no AI service of its own: to turn it on, open AI assistant: settings from the command palette and choose a provider. Use your own Anthropic API key, or any OpenAI-compatible endpoint, such as a model running on your computer with Ollama (http://localhost:11434/v1, no key needed). The key is kept in the keychain (desktop) or encrypted in the browser (web app).

Something is sent only when you ask: the task, the request and, to explain or suggest tests, its response. Secret values are replaced by *** before anything leaves the app, and so are credentials typed into headers, URLs or bodies. What the assistant proposes is shown to you first and added as an unsaved change; it never saves anything itself.

Start from an OpenAPI spec

Choose Import OpenAPI… in the command palette, the From OpenAPI tile of the New… dialog, or drop a spec on the window. The wizard reads OpenAPI 3.x and Swagger 2.0, as JSON or YAML, a multi-file spec (pick the folder or a .zip), a pasted spec or a URL. On the web, a server that does not allow the browser to read the spec is fetched through the paired companion (rt agent); references to other files of the same server come along.

It shows what is in the spec (operations per tag, servers, auth), then lets you choose the operations, how requests are grouped and named, and which servers become environments, with names such as Production and Staging. The result is a new collection or a folder of the open one, with a plain-language report of what could not be carried over. By default the spec is kept next to the requests and named in opencollection.yml (extensions.requesttailor.contract.spec), so the app can check against it.

With a spec in the collection, sending a request that matches an operation first checks what the spec requires. If a path parameter, a required query parameter or header, a variable such as baseUrl, or a required body is missing or does not fit the schema, Ready to send? asks for it in a form built from the schema, instead of sending into an error. Fill and send (⌘/Ctrl+Enter) writes the values to the request like any edit, unsaved; baseUrl and auth values go to the environment, secrets only to the keychain. Send anyway and Don't ask for this request are always there. After the response, a small badge says whether status, headers and body match the spec, with the differences one click away; it never blocks anything. The command line does the import with rt import openapi.

Mock a service from its examples

Requests can keep saved examples: a request and the response it got (OpenCollection examples, also carried over by the Postman import). rt mock serves them, so the app, a front end or a test can work before the real service exists:

rt mock . --env Local --port 4010

An incoming request matches an example by method and path: the path of the request's URL, where :id, {id} and unresolved {{variables}} match any segment, and scheme, host and a leading {{baseUrl}} are left out. With --env, the environment's variables are filled in first, so {{baseUrl}}/users/:id with baseUrl = http://localhost:4010/api becomes /api/users/:id. When several examples fit, the one whose saved request matches best wins: its path, query parameters, headers and body (JSON is compared as JSON). A request without a matching example gets 404 with a JSON list of all routes. The mock listens on 127.0.0.1 unless you pass --host, allows CORS for the web app, and logs every request to the terminal. It prints the routes at start.

Write documentation of a collection

rt docs turns a collection into one static HTML page with a stylesheet: folders, requests with method, URL, description and docs, parameters, headers, body, the type of auth, and the saved examples.

rt docs . --out public/api-docs --env Staging

The page runs no scripts, loads nothing from other servers and follows the system's light or dark mode, so it can be published as it is, for example with GitHub Pages. Secret values never appear: secret variables stay {{name}}, auth shows only its type and the variables it uses, and anything the secret scanner sees as a credential is shown as *** (the command tells you how many). With --env, the environment's non-secret variables are filled in.

Check the numbers

The performance budgets are measured on every build. The benchmark measures the same numbers for other API clients installed on the same machine:

npm run build -w apps/desktop
node scripts/bench/run.mjs --browser

It writes the results with the machine and every version to bench/results/. It installs nothing and starts other apps with an empty profile and without network access for their web content.
