Collections as files

The folder is the collection. The app reads it and writes changes back; it keeps no copy of its own.

Layout

my-api/
  opencollection.yml        the collection: name, default headers, auth, variables
  users/
    folder.yml              optional: folder name, order, defaults for its requests
    get-user.yml            one request per file
    create-user.yml
  environments/
    Local.yml               one file per environment
    Staging.yml

A folder inside the collection that has its own opencollection.yml is a separate collection.

A request

info:
  name: Get user
  type: http
  seq: 1

http:
  method: GET
  url: "{{baseUrl}}/users/{{userId}}"
  headers:
    - name: Accept
      value: application/json
  auth: inherit

auth: inherit takes the authentication of the folder or the collection. The URL is the truth for the query string; query parameters in a params list only mirror it.

OpenCollection

The files follow OpenCollection 1.0, the YAML format Bruno writes, so Bruno collections in that format open unchanged. OpenCollection allows no unknown fields; data of RequestTailor's own goes into the extensions section of opencollection.yml.

Reading and writing are exact. Opening a collection and saving it without changes gives byte-identical files, comments and formatting included. When you change one request, only that part of that file changes, so diffs show what you did and nothing else. The test suite checks this on every commit against a corpus of 86 Bruno collections.

Importing

Imports create a new collection folder from another tool's export:

SourceVersions
Postmancollections v2.0 and v2.1, with environment and globals files
Insomniav4 and v5 exports
OpenAPI3.0 to 3.2
cURLcommand lines
HAR1.2
.httpVS Code REST Client and JetBrains HTTP Client, with their environment files

Every import comes with a loss report that lists what could not be carried over exactly, with its location and whether it was dropped or approximated. Secret values from the source are never written; the variables are created as secrets without a value. Plugins can add importers, such as the OData plugin's $metadata importer.

Git

The desktop app has Git built in, without a staging area: choose the changed files, write a message, commit. Branches, pull, push and conflict resolution are in the same view. Operations that change files on disk refuse while you have unsaved changes. In the web app, pull and push go through the rt agent companion.
