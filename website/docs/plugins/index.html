Plugins

A plugin is a single WebAssembly file. The same file runs on the desktop, in the web app and in rt.

What a plugin can do

HookWhen it runs
PrepareBefore every send, after authentication and before signing; it can change the request
ResponseAfter every response; it can add notes
TabsAdds tabs to the request editor, the response view or the collection, drawn from declarative blocks (text, tables, trees, forms, buttons)
ImportersConverts files in the import dialog and in rt import into a collection, with a loss report

The sandbox

  • No native code: plugins are WebAssembly only, run by an interpreter that works the same everywhere.
  • No file system, no threads, and no network except through the host's HTTP call.
  • Every call runs in a fresh instance with a fuel limit and a memory limit of 64 MiB.
  • Plugins never see secret values: requests and responses reach them masked.

Permissions

A plugin declares in its manifest what it needs, and you see that before installing it:

PermissionAllows
networkHTTP requests to the listed hosts only ({request} means the host of the request being sent)
storageA private key-value store per plugin and device
variablesReading the non-secret variables in scope

Writing a plugin

Plugins are written in Rust with the plugin SDK and built with one command:

node scripts/build-plugins.mjs hello    # builds plugins/hello to target/plugins/hello.wasm
rt send request.yml --plugin target/plugins/hello.wasm --pretty

The full guide with a working example, the testing tools and the versioning rules is plugins/README.md; the binary interface is specified in API.md. A TypeScript SDK has the types and a test host; building plugins from TypeScript is not available yet.

Third-party plugins are welcome. Name them so it is clear they are your own, for example Acme Tools for RequestTailor; see the trademark policy.
