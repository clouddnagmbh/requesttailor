Safety and quality tools

Guards against sending the wrong thing to the wrong system, and checks that keep a collection correct over time. Everything runs locally and in your pipeline.

Production guard

An environment counts as production when its agent policy says so, or, without a policy, when its name is prod, prd or contains the word live. The app then draws a red frame, labels the send button Send to PRODUCTION and marks the environment switch. A writing request (anything but GET, HEAD, OPTIONS and TRACE, a GraphQL mutation, gRPC) asks first; Enter confirms, Esc cancels, and Don't ask again is remembered per device. The core, not the interface, decides what writes. rt send and rt run print a PRODUCTION: line on stderr and add it to the report; they never refuse because of it.

Send again on every save

rt send users/get-user.yml --env Local --watch

Watches the request, its body file, opencollection.yml, the folder files above it, the environment and its companion files, and sends again after each change within 500 ms. It prints one line per send: 200 12 ms 34 B same or changed: $.name. Only reading requests are sent; --allow-writes adds writing ones, never against production. --json prints one report per line.

Snapshots

Freeze a response as a snapshot: the status, a safe list of headers and the body, with paths you choose to ignore (timestamps, ids). It is saved as <request>.snap.json next to the request, and the request gets one assertion, res matchesSnapshot. rt send and rt run compare and never write; rt snapshot update [path…] [--all] or the app refreeze. Checking 1000 snapshots takes at most 150 ms. Older builds that do not know the operator report the assertion as failed, never as passed.

Lint

rt lint . --format github --min-score 80 --fail-on error

Checks a collection for requests without tests, hard-coded hosts, unused variables and duplicate names, and prints a health score from 0 to 100. It reads files and sends nothing. Exit code 7 when a finding reaches --fail-on or the score is below --min-score; output as text, json or github annotations. Rules and levels live in extensions.requesttailor.lint; --rule id=level overrides them. 1000 requests take at most 500 ms.

Compare environments

rt compare-env . --env Staging --env Production --fail-on-diff

Sends the reading requests of a folder in two or more environments (the first is the reference) and lists what differs in status, headers and JSON body. Writing requests are skipped and named, secret values never appear. 100 requests take at most 500 ms. The app has the same view.

Test-data journal

With Track test data on for a collection, the app and rt keep a list of the successful writing requests of a session: method, URL, status and what the response says about the created or changed thing. rt journal revert <id> --with <request-file> puts one back with a request you choose, filling {{journal.id}}, {{journal.location}} and {{journal.etag}} from the entry. That request is sent like any writing request: guard, audit log, and for production only with --yes-production. The journal keeps no bodies and no header values, and it cannot undo what has no undo request, such as OData draft actions. Plugins can supply clean-up rules as data; the OData plugin has them.

Two-user access check

rt access check orders/get-order.yml --as UserA --as UserB --json

Sends one request as user A (an environment). If the answer holds an object, it asks for the same object as user B and reports broken object or function access with masked evidence. It uses only ids user A saw, sends two requests, at most --rate per second (default 5), and a writing request only with --allow-writes, never against production. Exit code 4 when access is broken, 5 when the send guard refused, 2 when the check did not run. Use it only with accounts you own.

Smallest failing request

rt shrink orders/create.yml -e Staging --predicate status=500

Sends variations of a failing request, with fewer headers, query parameters, cookies and body fields, and prints the smallest one that still fails. A predicate is status=500, 5xx, assertion[=NAME], body~PATTERN, header=NAME, no-header=NAME or last. At most 100 probes and 120 seconds by default; --keep header:Authorization keeps a part. A request with 200 parts and one cause needs at most 60 sends. Writing requests only with --allow-writes, never against production. Exit code 0 found, 1 not reproducible, 5 blocked by the guard.
