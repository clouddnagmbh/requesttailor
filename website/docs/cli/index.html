Command line: rt

rt runs the same core as the apps. What is green in the app is green in the pipeline.

rt send <request-file> [--env NAME] [--var NAME=VALUE]... [--plugin FILE]... [--pretty]
rt run [FOLDER] [--env NAME] [--var NAME=VALUE]... [--data FILE] [--reporter NAME[=FILE]]...
rt import <file>... --out DIR [--format FORMAT] [--json]
rt import openapi <file|url>... --out DIR [--names operation-id] [--group tag|path|flat] [--keep-spec] [--json]
rt scan [PATH]... [--json]
rt snapshot update [PATH]... [--all] [-e NAME] [--var NAME=VALUE]...
rt mock [FOLDER] [--env NAME] [--port PORT]
rt docs [FOLDER] --out DIR [--env NAME]
rt lint [FOLDER] [--format text|json|github] [--min-score N] [--fail-on warn|error] [--rule ID=LEVEL]...
rt compare-env [FOLDER] --env A --env B... [--json] [--ignore-env-values] [--fail-on-diff]
rt access check <request-file> --as ENV-A --as ENV-B [--allow-writes] [--b-must-be-denied] [--rate N]
rt shrink <request-file> [-e ENV] [--predicate P] [--keep PART]... [--max-probes N] [--max-seconds N]
rt journal [list | revert ID --with REQUEST-FILE | clear] [-C COLLECTION] [--yes-production]
rt inbox [--port PORT] [--status CODE] [--json]
rt diff [REV | REV..REV] [--json] [COLLECTION]
rt merge-driver BASE OURS THEIRS [PATH]
rt bisect --good REV --bad REV [--env NAME] [--json] [FOLDER]
rt changelog REV..REV [COLLECTION] [--out FILE]
rt mcp [COLLECTION] [--var NAME=VALUE]... [--env-default NAME]
rt mcp-test [PATH]... [-e NAME]
rt mcp-demo [--http] [--port PORT]
rt approvals | approve ID | deny ID
rt agent [--port PORT] [--allow-origin ORIGIN]... [--allow-secrets]
rt --help | --version

rt --help is the complete reference and is what this page follows. Commands named there that are not described on this page are not part of the current build.

rt send

Sends one request. The collection is the nearest folder above the request file that contains opencollection.yml.

OptionMeaning
-e, --env NAMEUse the environment NAME
--var NAME=VALUERuntime variable with the highest precedence, repeatable; use it to pass secrets from the pipeline
--plugin FILERun a plugin's hooks for this send, for example target/plugins/odata.wasm
--body-limit BYTESKeep at most this many body bytes in the report (default 10 MiB)
--prettyIndent the JSON
--no-plugins, --no-scripts, --no-promptSkip installed plugins, skip scripts (declarative assertions still run), fail instead of asking for an OAuth login
--cookie-jar FILESend cookies from FILE and store new ones in it
--watch, --allow-writesSend again on every change of the request and its files; see send again on every save
--timing, --tracePrint the one-line timing bar or the trace id on stderr; see timing and trace
--checksPassive response checks, one line each on stderr and in the report; see response checks
--all-pages, --max-pages NFollow and merge the pages of a reading request (default 20, at most 1000); see pagination
--view NAME, --view-expr EXPRPrint what a saved view or a JSONPath expression picks, not the report
--respect-limits, --max-wait TWait for announced rate limits (also with rt run)
--sse, --message TITLE, --duration S, --until-closeSessions: read a response as Server-Sent Events, or open a WebSocket or gRPC request and print the message history

The output is one JSON object, the send report: what went on the wire (secrets as ***), the response with status, headers, body and timing, the variables used and their origin, unresolved placeholders and any error. The web app produces the same report.

Exit codeMeaning
0A response arrived, whatever its HTTP status
1No response: connection, DNS, TLS, timeout, too many redirects
2Usage error, no collection, invalid files, or the request is not in the collection
3The request could not be prepared: unknown environment, invalid URL, unsupported auth, unreadable body file
4A response arrived, but a test or assertion failed
5A policy of this installation refused the request; nothing was sent
7rt lint found what it was told to fail on

A status check in a pipeline, with jq:

rt send health/status.yml --env CI --var token="$API_TOKEN" \
  | jq -e '.response.status == 200'

rt send, rt run and rt mcp read the value of a secret variable from the OS keychain, where the desktop app keeps it for this collection and environment, so a request sends from the command line exactly as it does in the app. --var wins over the keychain. Without a keychain (a CI runner), pass the value with --var or read it from a secret manager.

rt run

Sends every request of a collection, or of one folder, in order and reports tests and assertions: the command for pipelines. It uses the same core, scripts, plugins and auth as the apps. Variables that scripts set carry over to the following requests of the run, never into files.

rt run api/users -e Staging --var token="$API_TOKEN"
rt run . --data users.csv --reporter junit=reports/junit.xml
OptionMeaning
--data FILECSV or JSON; each row's values are variables of one iteration
--iterations N, --delay MSRepeat the run, wait between requests
--respect-limits, --max-wait TWait for the rate limits servers announce (default off); a wait longer than T (60s, at most 600s) ends the run with the reason
--bailStop at the first failed request, test or assertion
--reporter NAME[=FILE]text, json or junit, repeatable
--no-scriptsDo not run scripts; declarative assertions still run

Exit code 0 when every request got a response and every test and assertion passed, 4 when a request, test or assertion failed, 2 on a usage error, 3 when secrets or plugins could not be set up.

rt import

rt import shop.postman_collection.json prod.postman_environment.json --out ./shop
rt import api.yaml --format openapi --out ./api --json

Prints the loss report. Exit code 0 once the collection is written, 2 if the input cannot be read or --out is not empty.

rt import openapi takes the same choices as the app's OpenAPI wizard: one spec file (OpenAPI 3.x or Swagger 2.0), the files of a multi-file spec, a .zip, or a URL (the files its relative references name are fetched too, from the same server). --names operation-id names requests after the operationId, --group chooses the folders, and --keep-spec keeps the spec in the collection as its contract spec.

rt import openapi petstore.yaml --out ./petstore --names operation-id --keep-spec
rt import openapi https://api.example.com/v1/openapi.yaml --out ./api --json

rt scan

Finds credentials in collection files (see secret scanner). Exit code 0 when clean, 1 with findings, 2 if a path cannot be read. As a Git pre-commit hook:

#!/bin/sh
files=$(git diff --cached --name-only --diff-filter=ACMR -- '*.yml' '*.yaml' '*.json')
[ -z "$files" ] && exit 0
exec rt scan $files

Git for APIs

These commands read the collection from Git without a checkout and compare requests field by field, not line by line. A revision is a commit id, a branch, a ref or HEAD, optionally with ~N or ^.

rt diff

rt diff                  # saved files against HEAD
rt diff HEAD             # a commit against its parent
rt diff main..feature --json

One line per changed field (URL, method, header, parameter, body, auth, script, assertion, setting) of each request, folder and environment; renames show as moved. Secret values never appear. Exit code 0, also when there are differences.

rt merge-driver

Lets Git merge collection files field by field. Set it up once per repository:

git config merge.requesttailor.driver "rt merge-driver %O %A %B %P"
echo "*.yml merge=requesttailor" >> .gitattributes

Two branches that change different fields of one request then merge cleanly in git merge, pull, rebase and cherry-pick. Only the same field changed differently on both sides is a conflict (exit 1): the file keeps your value with theirs in a comment above it, and the app resolves it per field.

rt bisect

rt bisect --good v1.4.0 --bad HEAD --env Staging

Finds the first commit at which a request, test or assertion fails, running each candidate from Git with today's environments and secrets. 50 commits take at most 7 runs. Exit code 0 when found, 4 when nothing fails.

rt changelog

rt changelog v1.4.0..HEAD > CHANGELOG-api.md

Markdown with the changes of the OpenAPI spec between two revisions, breaking changes first with the requests they affect, then the changes of the collection. The spec is openapi.yaml (or .yml, .json) next to the collection or at the repository root, or the path in extensions.requesttailor.contract.spec of opencollection.yml.

Two more sections follow when the collection has the files: GraphQL for a schema in SDL (extensions.requesttailor.contract.graphql, or schema.graphql next to the collection or at the repository root) and Protobuf for the .proto files of the collection’s Protobuf settings and what they import. Each lists the breaking changes first, with the GraphQL requests that select a changed field and the gRPC requests that call a changed method or reach a changed message.

rt snapshot

rt snapshot update writes the snapshot files (<request>.snap.json) anew from a fresh response; --all takes every request with a snapshot assertion. rt send and rt run only compare. Exit code 0 when written, 2 on a usage error. See snapshots.

rt mock and rt docs

rt mock serves the saved examples of a collection as a local API, and rt docs writes a collection as one static HTML page; both are described in getting started.

rt lint

Health score and findings of a collection; exit code 7 when a finding reaches --fail-on or the score is below --min-score. --format github prints annotations for GitHub Actions. See lint.

rt lint . --format github --min-score 80

rt compare-env

Sends the reading requests in two or more environments and lists what differs. Exit code 0 even with differences; --fail-on-diff exits 1 for them. See compare environments.

rt access, rt shrink, rt journal

rt access check is the two-user access check (exit code 4 when access is broken), rt shrink reduces a failing request to its smallest form (exit code 1 when not reproducible), rt journal lists test data a session wrote and puts it back with a request you choose. Writing requests need --allow-writes (or --yes-production for the journal) and never run against production otherwise. See safety and quality tools.

rt inbox

Listens on 127.0.0.1 (default port 47855), prints every request it gets and answers with a fixed reply. In memory only, no tunnel. See webhook inbox.

rt mcp-test and rt mcp-demo

rt mcp-test runs saved MCP tests (*.mcp.yaml) against their servers and prints JSON; exit code 0 when all passed, 4 when a test failed, 1 when a server could not be reached. rt mcp-demo is a demo MCP server with fake data for trying any MCP client, on stdio or with --http on 127.0.0.1:47850. See the demo server.

rt mcp

Offers a collection to AI agents over the Model Context Protocol. See MCP server.

rt agent

The web app runs in the browser, so the browser's rules apply: no request to a server without CORS headers, no client certificates. rt agent is a companion on your machine that sends such requests for the web app. It listens on 127.0.0.1 only, checks the Host and Origin of every request, pairs with the web app through a single-use code printed in your terminal, and keeps its tokens in memory only. With --allow-secrets it also reads secrets from secret managers for the web app.

The full reference, including the security model, is crates/rt-cli/README.md.
